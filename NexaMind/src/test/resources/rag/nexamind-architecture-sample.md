# NexaMind 架构样例

NexaMind 是一个面向 AI 应用开发的智能体平台。平台将模型服务、MCP 工具、RAG 知识库和会话管理组织为可组合能力，并通过前后端分离架构向用户提供智能体创建、调试、发布与监控功能。

## 分层架构

接口层负责接收 HTTP 请求、校验输入参数并转换响应对象。应用层负责编排用例，包括用户上下文、计费检查、工作区初始化和事务边界。领域层保存智能体、知识库、工具和会话的核心规则。基础设施层提供 PostgreSQL、RabbitMQ、对象存储、向量检索和外部模型调用的实现。

这种分层方式让核心业务规则不依赖具体数据库或模型供应商。新增模型协议、存储实现或消息队列消费者时，可以通过接口与适配器扩展，而不需要修改上层业务流程。

## 智能体创建

用户在前端填写名称、系统提示词、欢迎语、工具、知识库和多模态开关。前端通过 REST API 提交创建请求，后端控制器完成参数校验并取得当前用户。应用服务随后执行创建额度检查，组装领域实体，持久化智能体并初始化默认工作区，最后返回可供前端展示的数据对象。

工具和知识库以标识列表绑定到智能体。运行对话时，系统根据发布版本加载配置，构造模型请求，并将工具规格和检索结果加入上下文。该方式将“配置阶段”和“运行阶段”分离，便于版本管理和问题追踪。

## RAG 处理链路

知识库文件进入系统后，根据文件类型完成解析和结构化清洗。长文本按标题、段落与长度限制切分为多个片段，再调用 Embedding 模型生成向量并写入 pgvector。用户提问时，系统生成查询向量，执行相似度检索，并可结合 HyDE 和重排提高召回质量。

检索到的片段会附带来源、页码和知识库标识等元数据。应用服务将这些片段与系统提示词、历史消息和用户问题组合为模型上下文。模型生成回答后，系统保存消息、用量和执行轨迹，以便监控、计费与后续复盘。

## MCP 工具调用

MCP 模块将外部服务描述为模型可理解的工具规格。模型决定调用工具后，平台校验参数并通过网关转发请求。工具执行结果回到会话流程，再由模型整理为最终回答。容器管理模块为需要隔离运行的工具提供独立工作区，并记录容器状态和资源使用情况。

## 工程部署

开发环境使用 Docker Compose 编排前端、后端、PostgreSQL 和 RabbitMQ。环境变量集中管理端口、数据库、管理员账户、向量存储和对象存储配置。健康检查与依赖顺序用于减少服务尚未就绪时的启动失败，日志和执行轨迹用于定位跨模块问题。
